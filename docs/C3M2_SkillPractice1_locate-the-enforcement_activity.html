Find where each boundary is enforced

Three boundaries govern any use of data: whether it can be reached, whether it fits the named use, and whether the organization is permitted to use it that way. A boundary is enforced when a system would stop you from crossing it. A policy, a review, or an approval can state a boundary without enforcing it, and a boundary enforced nowhere exists only in the interview.

A manufacturer’s service function is building an assistant that drafts responses to warranty claims for agents to review. It reads claim records from four regional claims systems through the consolidated data platform. The readiness file holds six statements about how the assistant is controlled.

Reach: the system can technically get to the data. Fit: the data is trustworthy for this named use, judged by its origin, its currency, its completeness, and how well it represents the conditions the system will meet. Permission: law, contract, or policy allows the organization to use the data this way.

Place each statement under the boundary it enforces. If no system would stop anyone from crossing the boundary, place it under Enforces nothing.

Where each boundary stands

What enforces each boundary in the readiness file
BoundaryWhat enforces it
ReachThe access layer.
Fit for this useThe load-date check, for currency only. Origin, completeness, and representativeness have no enforcement point.
PermissionNothing. The boundary lives in a policy, a form, and an email.

A boundary that nothing enforces is a finding. It tells the sponsor which boundary rests on trust alone.
