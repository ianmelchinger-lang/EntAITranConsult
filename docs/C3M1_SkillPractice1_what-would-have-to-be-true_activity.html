Ask what would have to be true

A demonstration shows what a model can do. Whether it creates value depends on the organization around the model, and the conditions that decide that are the dimensions of readiness. Ask what would have to be true here, not whether the technology can do the thing, and most of the answers sit outside the software.

A manufacturer’s warranty-claims assistant did well in one region. Its transformation lead is weighing an extension to all four. Each statement below would have to hold for that extension to create value. Some describe the software. The rest describe the organization the software would work inside.

Place each statement. Choose The software if it describes what the assistant does. Otherwise choose the dimension of readiness it describes.

Data
The records the assistant reads are complete, consistent, and current.
Workflows
The work around the assistant is designed so its output has somewhere to go, including for cases it cannot handle.
Ownership
A named person answers for each output and for each decision made from it.
Adoption
The people who do the work use the tool as designed instead of working around it.
Governance
Written rules, reviews, and records show the arrangement is under control.
Measurement
Someone can see whether the tool delivers what justified it, and what it costs elsewhere.
Trust
The people who rely on an output have grounds to rely on it and can check it against something they know.

Second pass: take one dimension away

Suppose the assistant is as accurate as ever and every statement about the software still holds. Choose one dimension and imagine it missing. Nothing here is checked.
