Set the tier by what a mistake costs

Tiered control sets how strong the access control and governance is for a category of data, according to what getting that category wrong would cost. Someone has to decide each tier, use case by use case, because the data doesn’t tier itself. Two errors are possible, and they are not the same size. Over-controlling low-stakes data costs speed and goodwill, and you can loosen the control next quarter. Under-controlling high-stakes data costs something you can’t give back, because an exposed record stays exposed.

A manufacturer’s service function is building an assistant that drafts responses to warranty claims. An agent reads every draft against the current coverage terms before anything is sent. The assistant draws on eight categories of data.

Put a category in the heavier tier when a wrong disclosure or a wrong value can’t be taken back. Put it in the lighter tier when the cost is speed or convenience you can recover. Each card says what happens if that category goes wrong.

What one uniform rule does

One access rule covers all eight categories: a ticketed request, approved by a manager. It is the standard every team could meet.
